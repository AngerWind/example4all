# 原教程错误与修正记录

本文件记录融合过程中发现的明显错误、过时写法或需要补充前提的内容。新生成教程已经采用修正后的说法。

## 1. void 可以返回 null

原说法：

```ts
function fn(): void {
  return null; // 可以
}
```

修正：

在开启 `strictNullChecks` 时，`void` 函数不能返回 `null`，可以不返回或返回 `undefined`。

```ts
function fn(): void {
  return undefined;
}
```

只有关闭 `strictNullChecks` 时，`null` 才可能被宽松接受。现代项目建议开启 `strict`。

## 2. any 示例注释写成“不保存”

原片段：

```ts
let c1: any = 1;
let s: string = c1; // 不保存
```

修正：

这里应表达为“不报错”。`any` 可以赋值给任意类型，会绕开类型检查。

```ts
let c1: any = 1;
let s: string = c1; // 不报错，但不安全
```

## 3. never 示例不是严格合法的 never 函数

原片段大意：

```ts
function error(message: string): never {
  if (message === "xxx") {
    throw new Error(message);
  }
}
```

问题：

如果 `message !== "xxx"`，函数会正常结束并返回 `undefined`，不符合 `never`。

修正：

```ts
function error(message: string): never {
  throw new Error(message);
}
```

或：

```ts
function loopForever(): never {
  while (true) {}
}
```

## 4. 函数类型示例中参数类型不兼容

原片段：

```ts
let d: (a: string, b: number) => number = function(n1: number, n2: number): number {
  return n1 + n2;
}
```

问题：

变量类型要求第一个参数是 `string`，实现函数第一个参数却是 `number`。

修正：

```ts
let d: (a: number, b: number) => number = function(n1: number, n2: number): number {
  return n1 + n2;
};
```

## 5. 箭头函数示例中使用了不存在的变量

原片段：

```ts
let add = (n1: number, n2:number):number => {
  return a +b
}
```

问题：

`a`、`b` 未定义。

修正：

```ts
let add = (n1: number, n2: number): number => {
  return n1 + n2;
};
```

## 6. type 拼写错误

原片段：

```ts
type myType = 1 | 2 | 3;
let a: myTpye = 1;
```

修正：

```ts
type MyType = 1 | 2 | 3;
let a: MyType = 1;
```

## 7. 数组类型别名语法错误

原片段：

```ts
type myArr = (string, number)[]
let arr: myArr = [1, "b"]
```

问题：

`(string, number)[]` 不是合法的联合数组写法，也不是元组数组写法。

修正：

```ts
type MyUnionArray = (string | number)[];
let arr1: MyUnionArray = [1, "b"];

type MyTupleArray = [string, number][];
let arr2: MyTupleArray = [["b", 1]];
```

## 8. 抽象类示例类名不一致

原片段：

```ts
abstract class Animal {
  abstract run(): void;
}

class Dog extends Animals {
  run() {}
}
```

问题：

定义的是 `Animal`，继承时写成了 `Animals`。

修正：

```ts
abstract class Animal {
  abstract run(): void;
}

class Dog extends Animal {
  run() {}
}
```

## 9. getter 和 setter 说明反了

原文大意：

读取属性的方法叫做 setter，设置属性的方法叫做 getter。

修正：

- `getter`：读取属性。
- `setter`：设置属性。

```ts
get name() {
  return this._name;
}

set name(value: string) {
  this._name = value;
}
```

## 10. CommonJS 导出对象写成 module.export

原片段：

```js
module.export.a = a;
module.export = { a, b };
```

修正：

```js
module.exports.a = a;
module.exports = { a, b };
```

同时，`exports` 是 `module.exports` 的初始引用。可以写：

```js
exports.b = b;
```

但不能写：

```js
exports = { a, b };
```

因为这只是修改了局部变量 `exports` 的指向。

## 11. Promise 拼写错误

原文中 `Promise` 写成了 `Promis`。

修正：

```ts
const modulePromise = import("./module.js"); // Promise<Module>
```

## 12. declare module 示例语法错误

原片段：

```ts
declare module "abcde" {
  export let c: {
    let cd: string
  }
}
```

问题：

对象类型里不能写 `let cd`。

修正：

```ts
declare module "abcde" {
  export let c: {
    cd: string;
  };
}
```

## 13. typeof 不能获取函数类型的说法不准确

原说法：

`typeof` 只能获取变量和属性的类型，不能获取函数的类型。

修正：

函数名本身是一个值，因此可以使用类型位置的 `typeof` 获取函数类型：

```ts
function add(a: number, b: number) {
  return a + b;
}

type Add = typeof add;
type AddReturn = ReturnType<typeof add>;
```

但不能写：

```ts
// type X = typeof add(1, 2); // 错误
```

## 14. 索引签名示例属性类型冲突

原片段：

```ts
type A = {
  name: string;
  [key: string]: number;
}
```

问题：

字符串索引签名要求所有字符串属性的值都是 `number`，但 `name` 是 `string`。

修正：

```ts
type A = {
  name: string;
  [key: string]: string | number;
};
```

或：

```ts
type A = {
  [key: string]: number;
};
```

不要同时放入不兼容的明确属性。

## 15. moduleResolution 默认值描述过时

原文大意：

`moduleResolution` 未指定时默认值为 `Classic`。

修正：

这在早期 TypeScript 语境下可以理解，但现代 TypeScript 会根据 `module` 等配置决定默认策略。当前项目中更应按实际环境选择：

- Node.js ESM/CJS：`node16` 或 `nodenext`。
- 打包工具项目：`bundler` 或框架模板默认。
- 老项目：可能仍是 `node`。

## 17. webpack 依赖数量描述不一致

原文安装命令：

```bash
npm i -D webpack webpack-cli webpack-dev-server typescript ts-loader clean-webpack-plugin
```

随后说“共安装了 7 个包”，并列出了 `html-webpack-plugin`。

修正：

```bash

```

## 18. @babel-loader 名称错误

原文把 `babel-loader` 写成 `@babel-loader`。

修正：

包名是：

```bash
npm install -D babel-loader
```

不是 `@babel-loader`。

## 19. “在 TS 中使用 JS 必须为 JS 定义声明文件”说法过绝对

修正：

更准确的说法是：

- 如果 `allowJs` 开启，TypeScript 可以把 JS 文件纳入项目。
- 如果需要对 JS 做类型检查，可以用 `checkJs` 和 JSDoc。
- 如果 TS 文件导入没有类型的 JS 模块，为了获得准确类型，应该提供 `.d.ts` 或安装类型包。

所以不是所有 JS 都“必须”有 `.d.ts`，但没有类型声明时类型安全和编辑器体验会变差。
