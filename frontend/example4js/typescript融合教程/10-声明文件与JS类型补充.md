# 声明文件与 JS 类型补充

## 1. 什么是 .d.ts 文件

在TS中有两种文件类型:

- .ts文件: 可以写类型, 也可以写可执行代码
- .d.ts文件: 只能包含类型信息, 在编译后不会生成.js文件, 只用于提供类型信息



## 2. TS 的两种文件类型

`.ts` 文件可以包含类型和可执行代码：

```ts
type Props = { a: number; b: string };

function add(a: number, b: number) {
  return a + b;
}
```

`.d.ts` 文件只包含类型声明：

```ts
type Props = { x: number; y: number };
export type { Props };
```

## 3. 内置声明文件

TypeScript 自带很多内置声明文件，例如：

- `lib.dom.d.ts`：`window`、`document`、DOM API。
- `lib.es2020.d.ts`：ES2020 标准 API。
- `lib.esnext.d.ts`：更新阶段的标准 API。

这也是为什么你在 TS 中能直接写：

```ts
document.querySelector("#root");
window.location.href;
```

这些类型不是你自己定义的，而是由 `lib` 相关声明文件提供。

## 4. 第三方库类型

第三方库类型通常有两种提供方式：

1. 库自己携带类型声明，并在 `package.json` 中通过 `types` 或 `typings` 指向入口声明文件。

2. 库没有内置类型，需要安装 `@types/*`。

   例如：

   ```bash
   npm install lodash
   npm install -D @types/lodash
   
   npm install express
   npm install -D @types/express
   ```

   React、Node 等也常见对应类型包：

   ```bash
   npm install -D @types/node
   npm install -D @types/react @types/react-dom
   ```

   如果库已经内置类型，就不需要再安装 `@types`。

   



### ts怎么查找类型信息

1. ts在解析文件的时候, 如果发现了

   ~~~ts
   import { x } from "pkg";
   ~~~

2. 查看 `node_modules/pkg`中的package.json

   ~~~json
   {
     "types": "index.d.ts"
   }
   ~~~

3. 如果package.json指定了types, 那么就使用这个文件中的类型信息

4. 如果没有types, 那么就fallback去查找`node_modules/@types/pkg`, 任何加载其中的.d.ts文件

   ~~~ts
   declare module "pkg"
   ~~~

   



## 5. 给本地 JS 文件补充类型

假设在你的TS项目中, 有一个js文件  `utils.js`：

```js
export let count = 10;
export let songName = "痴心绝对";

export function add(x, y) {
  return x + y;
}

export function changeDirection(direction) {
  console.log(direction);
}
```

如果你想要对这个js文件补齐类型信息, 那么可以创建同目录 `utils.d.ts`：

```ts
export declare let count: number;
export declare let songName: string;

export declare function add(x: number, y: number): number;

export declare function changeDirection(
  direction: "up" | "down" | "left" | "right"
): void;
```

然后在 TS 中使用, TS会自动加载和js同名的d.ts文件, 提供类型声明

```ts
import { count, songName, add } from "./utils";

console.log(count, songName, add(1, 2));
```





## 6. 给依赖库补充类型声明

在给第三方库补充声明的时候, 分为两种情况

1. 这个第三方类库根本就没有提供类型信息, 他就是一个普通的js库, 也没有发布@types
2. 第三方类库提供了类型信息, 但是还有一些在运行时可用的变量是通过动态注入的, 是根据用户的情况不同而不同的, 这部分变量的类型信息第三方类库没有办法提供, 这本来就是用户需要去填充的



然后还有一个需要明确的点是, 在ts中有两套类型定义系统

1. 使用命名空间来进行定义, 这种扩展方式出现的比较早期, 是ES Module还没有普及, JS还没有出现标准模块系统的时候就出现了的

   他的实现方式是这样的

   ~~~ts
   declare namespace HelloWorld {
     interface Request {
       user?: string;
     }
   }
   ~~~

   这样会定义一个命名空间Express, 并且这个命名空间中有一个Request类型

   **这样不管这个文件是在 `node_modules/@types`(三方项目)下, 还是在当前项目的`types`(自己的项目)下, 只要ts读取了这个文件, 那么他就会将这个Request添加到全局范围中, 这样你不管在任何的文件中, 都可以使用这个类型了, 也不需要import**

2. 另外一种就是模块化系统来定义, 随着 ES Module成为标准

   ~~~ts
   export type User = {
     id: string;
     name: string;
   };
   ~~~

   使用:

   ~~~ts
   import type { User } from "./types";
   ~~~

   使用这种方式, 需要进行export/import才能使用对应的类型





### 给JS库补充类型信息

假设你使用如下代码安装了一个JS的库, 而这个库就是一个普通的js库, 没有类型信息, 也没有发布@types

那么直接了当的就是使用模块化的体系给他补充类型

~~~shell
npm install legacy-lib
~~~

任何这样使用

~~~shell
import { foo } from "legacy-lib";

foo("hello");
~~~

那么在ts中, ts并不知道关于legacy-lib库的任何类型信息, 这个时候我们可以在当前项目中, 给这个依赖库补充类型信息

在`project根目录/types/legacy-lib.d.ts`目录下创建`legacy-lib.d.ts`文件

~~~ts
// legacy-lib.d.ts

// 这里不需要export, declare module的意思是给这个模块补充类型信息
declare module "legacy-lib" {
  export function foo(name: string): string;
  export function bar(x: number): number;
}
~~~

任何在tsconfig.json中添加

~~~js
{
  "include": ["types", "src"]
}
~~~

这样ts根据tsconfig.json中的 include / files / typeRoots 就能够加载到这个d.ts文件了, 任何知道legacy-lib这个模块的类型信息了

~~~ts
import { foo } from "legacy-lib";

foo("abc");   // ✔ 有类型提示
foo(123);     // ❌ 报错
~~~



### 对现有类型系统进行扩展

回到我们在最开始的分类的第二种情况, 如果第三方类库提供了类型信息, 但是还有一些在运行时可用的变量是通过动态注入的, 是根据用户的情况不同而不同的, 这部分变量的类型信息第三方类库没有办法提供, 这本来就是用户需要去填充的



在对这些模块进行补充类型的时候, 你首先要确定的就是他使用的是namespace还是module的体系来定义类型的

- 你在使用vite的时候, vite会自动帮你处理.env文件, 然后自动将`VITE_`开头这些变量挂在到`import.meta.env`下面, 所有你可以直接使用

  ```ts
  console.log(import.meta.env.VITE_API_URL); // Cannot find name 'API_URL'
  ```

  但是如果你直接使用的话, 那么ts会报错, 说不知道VITE_API_URL, 但是这个变量确实是可以在运行时使用的, 那么你就需要补充这个变量的类型, 建议放在`project/types/env.d.ts`中

  ```ts
  // project根目录/types/env.d.ts
  interface ImportMetaEnv {
    readonly VITE_API_URL: string;
    readonly VITE_APP_NAME: string;
  }
  ```
  
- 在使用script的时候, 有可能会自动将特定的变量挂在到window下, 这样你就可以直接使用了

  ```ts
  window.myApp = {
    version: "1.0"
  };
  ```

  但是你在直接使用`window.myApp`的时候, 就会报错, 找不到他的类型, 这个时候我们就需要给window扩展类型信息了

  因为window使用的是比较老的namespace的体系来定义类型的, 所以你也需要延续这种方式

  ~~~ts
  // 项目根目录/types/window.d.ts
  
  export {};
  declare global {
    interface Window { // 这里不需要声明所有的api, 因为同时声明两个相同的type, 那么会进行叠加, 所以这个window会叠加lib中定义的window
      myApp: {
        version: string;
      };
    }
  }
  ~~~

  之后你就可以正常使用`myApp`这个全局变量了

- 如果你是在nodejs中, 那么工具注入的全局可用的变量, 你可以这样来扩展

  ~~~ts
  // project/types/global.d.ts
  
  declare const API_URL: string;
  declare const NODE_ENV: "development" | "production";
  ~~~

- 如果你使用的是express, 那么express在接受请求的时候, 是可以直接将你的请求参数动态注入到req上面的

  ~~~ts
  app.get("/", (req) => {
    req.user?.id;
  });
  ~~~

  但是你在使用的时候, 就会报错找不到user的类型, 所以这个时候你就需要给这个user补充类型

  因为express可以使用module体系的语法来扩展, 所以使用下面的语法

  ~~~ts
  // 项目根目录/types/express.d.ts
  
  declare module "express" {
    interface Request {
      user?: {
        id: string;
      };
    }
  }
  ~~~

  

> 上面所有放在 `项目根目录/types`下的文件, 你都要在tsconfig.json中添加
>
> ```json
> {
>   "include": ["src", "types"]
> }
> ```





## 7. 专用的.d.ts文件

在ts中, `.d.ts`文件还有一个又是就是, 在编译之后ts会生成js文件, 但是.d.ts文件在编译之后会完全的消失的

所以你的类型可以专门放在一个.d.ts文件中, 所有的类型都放在其中

~~~ts
// aa.d.ts
export declare interface Position {
  x: number;
  y: number;
}
~~~

然后你可以这样使用

```ts
import {Position} from "./aa"
```

后面你就可以使用这个类型了



## 6. 声明变量、函数、类、接口

变量：

```ts
declare const version: string;
declare let count: number;
```

函数：

```ts
declare function add(a: number, b: number): number;
```

函数重载：

```ts
declare function add(a: number, b: number): number;
declare function add(a: string, b: string): string;
```

接口：

```ts
export interface Position {
  x: number;
  y: number;
}
```

类：

```ts
declare class Student {
  name: string;
  age: number;
  say(): void;
}
```

## 7. CommonJS 模块声明

如果 JS 使用 CommonJS：

```js
// a.js
let xa = 100;

function sayHi(msg) {
  console.log(msg);
}

module.exports = { xa, sayHi };
```

在真实项目中，更推荐给相对 JS 文件写同名 `.d.ts` 并导出：

```ts
// a.d.ts
export declare const xa: number;
export declare function sayHi(msg: string): void;
```

如果是声明一个包名模块，可以写：

```ts
declare module "hello" {
  export const xa: number;
  export function sayHi(msg: string): void;
}
```

如果模块本身导出一个函数，并使用 `module.exports = fn`：

```ts
declare function app(port: number): void;
export = app;
```

使用时：

```ts
import app = require("app");
app(3000);
```

## 8. 全局声明和模块声明

如果 `.d.ts` 文件没有任何顶层 `import` 或 `export`，里面的声明通常是全局声明：

```ts
// global.d.ts
declare const APP_VERSION: string;
```

如果有顶层 `export`，它就是模块声明文件：

```ts
// types.d.ts
export type Point = {
  x: number;
  y: number;
};
```

在模块声明文件中扩展全局类型，需要用 `declare global`：

```ts
export {};

declare global {
  interface Window {
    appVersion: string;
  }
}
```

## 9. 模块扩展

可以扩展已有模块中的类型：

```ts
// test1.d.ts
export interface A {
  a: string;
}
```

```ts
// test2.d.ts
import "./test1";

declare module "./test1" {
  interface A {
    b: string;
  }
}
```

这依赖 TypeScript 的声明合并机制，常用于扩展第三方库类型。

## 10. 在 JS 项目中逐步使用 TS

如果项目暂时还是 JavaScript，可以使用：

```json
{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "noEmit": true
  }
}
```

也可以在 JS 文件中使用 JSDoc：

```js
/**
 * @param {number} a
 * @param {number} b
 * @returns {number}
 */
function add(a, b) {
  return a + b;
}
```

迁移策略：

- 先启用 `allowJs`。
- 对关键 JS 文件启用 `checkJs` 或局部 `// @ts-check`。
- 给第三方或本地 JS 模块补 `.d.ts`。
- 逐步把核心文件从 `.js` 改成 `.ts`。
