# 类与面向对象

## JS 中已有的 class 能力

`class` 是 JavaScript 本身就有的语法，不是 TypeScript 独有。JS 已经支持 `class`、`constructor`、实例方法、静态方法、`extends`、`super`、getter/setter，以及 `#private` 运行时私有字段。

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  run() {
    console.log(`${this.name} 在跑`);
  }

  static create(name) {
    return new Animal(name);
  }
}

class Dog extends Animal {
  bark() {
    console.log("汪汪");
  }
}

const dog = new Dog("旺财");
dog.run();
dog.bark();
```

TypeScript 在 JS `class` 基础上增加类型能力：属性类型、构造函数参数类型、`public`、`protected`、`private`、`readonly`、`abstract`、`implements` 和 `override`。


## 1. 类的基本写法

TypeScript 的类建立在 JavaScript `class` 语法上，额外添加属性类型、访问修饰符、抽象类等类型能力。

```ts
class Person {
  name: string;
  age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }

  sayHello() {
    console.log(`大家好，我是${this.name}`);
  }
}

const p = new Person("孙悟空", 18);
p.sayHello();
```

如果属性有初始值，TypeScript 可以推断类型：

```ts
class Person {
  age = 18;
  gender = "男";
}
```

## 2. strictPropertyInitialization

开启 `strict` 后，类属性要么在声明时初始化，要么在构造函数中赋值：

```ts
class User {
  name: string;

  constructor(name: string) {
    this.name = name;
  }
}
```

如果属性确实会在框架或其他流程中赋值，可以使用 definite assignment assertion：

```ts
class User {
  name!: string;
}
```

不要滥用 `!`，它会绕开初始化检查。

## 3. 构造函数参数属性

TypeScript 支持在构造函数参数上直接声明属性：

```ts
class User {
  constructor(
    public name: string,
    private secret: string,
    protected id: number,
    readonly key: string
  ) {}
}
```

等价于先声明属性，再在构造函数中赋值。

## 4. public、protected、private

public在任何地方都可以访问, private只有内部可以访问, protected只有内部或者子类可以访问

```ts
class Animal {
    // public(默认值, 可以省略不写): 类内部、子类、实例外部, 哪里都能访问
    public name: string;

    // protected: 类内部 + 子类内部能访问, 实例外部不能访问
    protected age: number;

    // private: 只有当前类(Animal)内部能访问, 子类和实例外部都不行
    private secret: string;

    // 构造函数默认不写写就是public, 在任何地方都能调用
    constructor(name: string, age: number) {
      this.name = name;
      this.age = age;
      this.secret = "动物的秘密";
    }
    
    // 只有内部可以调用
    private constructor() {}
    
    // 只有子类和内部可以调用
    protected constructor() {}
    
    // public方法: 对外暴露的接口, 谁都能调
    public introduce(): void {
      // 类内部: 三种修饰符的成员都能访问
      console.log(`我叫${this.name}, ${this.age}岁, ${this.secret}`);
      this.breathe();   // ✅ 内部可以调protected
      this.metabolize(); // ✅ 内部可以调private
    }

    // protected方法: 类内部 + 子类能调, 实例外部不能调
    protected breathe(): void {
      console.log("呼吸...");
    }

    // private方法: 只有Animal内部能调, 子类也不能调
    private metabolize(): void {
      console.log("新陈代谢...");
    }
  }

  // ============================================================
  // 子类: protected能访问, private访问不到
  // ============================================================

  class Dog extends Animal {
    constructor(name: string, age: number) {
      super(name, age);
    }

    run(): void {
      this.name;       // ✅ public: 子类可以访问
      this.age;        // ✅ protected: 子类可以访问
      // this.secret;  // ❌ 报错: private连子类也不能访问

      this.introduce(); // ✅ public方法: 子类可以调
      this.breathe();   // ✅ protected方法: 子类可以调
      // this.metabolize(); // ❌ 报错: private方法子类也不能调
    }
  }

  // ============================================================
  // 实例外部: 只有public能访问
  // ============================================================

  const dog = new Dog("旺财", 3);

  dog.name;         // ✅ public属性: 外部可以访问
  // dog.age;       // ❌ 报错: protected属性, 实例外部不能访问
  // dog.secret;    // ❌ 报错: private属性, 实例外部不能访问

  dog.introduce();  // ✅ public方法: 外部可以调
  // dog.breathe(); // ❌ 报错: protected方法, 实例外部不能调
  // dog.metabolize(); // ❌ 报错: private方法, 实例外部不能调

  // 想从外部间接拿到private数据? 可以通过getter, setter
```

## 5. TS private 和 JS #private

TypeScript 的 `private` 主要是类型系统限制，编译到旧版本 JavaScript 后可能仍是普通属性。JavaScript 的 `#secret` 是运行时私有字段：

```ts
class User {
  #secret = "secret";

  getSecret() {
    return this.#secret;
  }
}
```

如果需要运行时真正私有，优先考虑 `#private`。如果只是做 TypeScript 类型层面的访问限制，`private` 更常见。

## 6. readonly

`readonly` 用来限制属性重新赋值：

```ts
class Person {
  readonly age: number;

  constructor(age: number) {
    this.age = age;
  }
}

const p = new Person(18);
// p.age = 20; // 报错
```

`readonly` 可以和访问修饰符组合：

```ts
class User {
  public readonly id: string;

  constructor(id: string) {
    this.id = id;
  }
}
```

## 7. getter 和 setter

访问器是 JavaScript 语法，TypeScript 在其基础上添加类型检查：

```ts
class Person {
  private age: number;

  constructor(age: number) {
    this.age = age;
  }

  get age() {
    return this.age;
  }

  set age(value: number) {
    if (value >= 0) {
      this.age = value;
    }
  }
}

const person = new Person(18);
person.age = 20;
console.log(person.age);
```

## 8. 静态成员

> 静态成员是js中就有的, 不是ts新加的, ts只是加了类型


静态成员属于类本身，不属于实例：

```ts
class Tools {
  static PI = 3.1415926;

  static sum(a: number, b: number) {
    return a + b;
  }
}

Tools.PI;
Tools.sum(1, 2);
```

## 9. 继承和 super

> 

```ts
class Animal {
  constructor(public name: string) {}

  run() {
    console.log(`${this.name} 在跑`);
  }
}

class Dog extends Animal {
  constructor(name: string, public age: number) {
    super(name);
  }

  bark() {
    console.log("汪汪");
  }
}
```

子类构造函数中必须先调用 `super()`，再使用 `this`。

## 10. 方法重写和 override

子类可以重写父类方法：

```ts
class Animal {
  run() {
    console.log("animal run");
  }
}

class Dog extends Animal {
  override run() {
    console.log("dog run");
  }
}
```

建议开启 `noImplicitOverride`，这样重写父类方法时必须写 `override`，能避免父类方法改名后子类悄悄失效。

## 11. 抽象类

> 抽象类是ts中的特性, js中没有abstract关键字

抽象类不能直接实例化，只能被继承：

```ts
abstract class Animal {
  abstract run(): void;

  sleep() {
    console.log("sleep");
  }
}

class Dog extends Animal {
  run() {
    console.log("dog run");
  }
}
```

抽象方法没有方法体，子类必须实现。

## 12. 类实现接口

js中没有implement, 只有ts中有

<font color=red>**implement在ts中也不是实现, 而是强制某个class必须满足某个类型结构, 如果少了, 多了就在编译的时候报错, 在编译为js之后就完全被抹除了**</font>

```ts
interface Singable {
  name: string;
  sing(): void;
}

class Person implements Singable {
  name = "jack";

  sing() {
    console.log("sing");
  }
}
```

因为只是implement只是限制结构, 所以也可以用在type定义的类型上面, 但是这个类型必须是静态可以确定的类型
```ts
  // type定义的对象类型, 完全可以implements
  type Animal = {
    name: string;
    run(): void;
  };

  class Dog implements Animal {   // ✅ 没问题
    name = "旺财";
    run() {
      console.log("跑");
    }
  }

  // ❌ 联合类型不行: 到底要实现A还是B? 没法确定
  type AorB = { a: string } | { b: string };
  class Foo implements AorB {}  // 报错
  
  // ❌ 交叉类型中含联合/无法静态解析的也不行
  // (纯对象交叉 type C = A & B 是可以的)
  
  // ❌ 基本类型当然更不行
  type Name = string;
  class Bar implements Name {}  // 报错
```

接口只检查实例侧结构，不检查类的静态侧成员。

## 13. 类型兼容性

TypeScript 采用结构类型系统。**<font color=red>两个类只要实例结构兼容，就可以互相赋值</font> **：

```ts
class Point {
  x!: number;
  y!: number;
}

class Point2D {
  x!: number;
  y!: number;
}

const p: Point = new Point2D();
```

但如果类包含 `private` 或 `protected` 成员，兼容性会更严格，通常要求这些私有/受保护成员来自同一个声明。
