## 1. 对象类型

对象类型可以直接使用字面量结构描述：

```ts
let user: {
  name: string;
  age: number;
  sayHi(): void;
};

user = {
  name: "jack",
  age: 18,
  sayHi() {
    console.log("hi");
  }
};
```

属性之间可以用分号或换行分隔。对象值本身仍然用逗号分隔：

```ts
type User = {
  name: string;
  age: number;
};

const user: User = {
  name: "jack",
  age: 18
};
```

## 2. 可选属性

属性后加 `?` 表示可选：

```ts
type User = {
  name: string;
  age?: number;
};

const u1: User = { name: "jack" };
const u2: User = { name: "rose", age: 18 };
```

`age?: number` 和 `age: number | undefined` 的区别

```ts
type A = { age?: number };              // 属性可以整个不写
type B = { age: number | undefined };   // 属性必须写, 但可以赋undefined

const a: A = {};                 // OK
const b: B = {};                 // 报错: 缺少age属性
const b2: B = { age: undefined }; // OK, 必须显式写出来
```

!!!读取可选属性时，要考虑它可能是 `undefined`：

```ts
function printAge(user: User) {
  if (user.age !== undefined) {
    console.log(user.age.toFixed());
  }
}
```

## 3. 只读属性

`readonly` 表示属性只能在初始化或构造阶段赋值，不能在外部重新赋值：

```ts
type User = {
  readonly id: string;
  name: string;
};

const user: User = {
  id: "u_001",
  name: "jack"
};

// user.id = "u_002"; // 报错
user.name = "rose";
```

`readonly` 是 TypeScript 的类型约束，不等于运行时不可变。对象内部嵌套值如果是引用类型，仍可能被修改：

```ts
type State = {
  readonly list: string[];
};

const state: State = { list: [] };
state.list.push("todo"); // 可以
// state.list = []; // 不可以
```

## 4. 索引签名

```ts
let c: {
    name: string, // 必须有一个string类型的name属性
    // 还可以有其他的属性, key是string类型, value是string | number类型
    // 这里的propName不是固定的, 只是随便取的一个名字, 可以改为key, k等其他名字
    [propName: string]: string | number 
};
c = {name: '猪八戒', age: 18, gender: '男'};
```

```ts
// !!! 注意, 索引签名 [propName: K]: T 的意思是, 这个对象所有的key都是K的子集类型, value都是T的子集类型, 并且他可以拥有更多这样的类型

// ❌ 报错，索引签名约束所有的属性key和value都是string类型, 但是age的value是number类型
// let b1: {
//   name: string, 
//   age: number, 
//   [propName: string]: string 
// };


// ✅ 改为 any 或联合类型
let c1: { 
    name: string, age: number, 
    [propName: string]: string | number
};

```

## 4. 多余属性检查（excess property check）

对象**字面量直接赋值**时，TypeScript 会做多余属性检查：多写了类型中不存在的属性会直接报错：

```ts
type User = {
  name: string;
};

const user: User = {
  name: "jack",
  age: 18 // 报错: 对象字面量只能指定已知属性, User中没有age
};
```

但是**先赋给变量、再传变量**，就不做这个检查（此时走的是类型兼容性检查，只要包含必需属性就算兼容）：

```ts
const obj = {
  name: "jack",
  age: 18
};

const user: User = obj; // OK, 不报错
```

这个规则同样适用于**函数参数传对象字面量**：

```ts
function printUser(user: User) {}

printUser({ name: "jack", age: 18 }); // 报错: 字面量直接传参会检查多余属性

const obj = { name: "jack", age: 18 };
printUser(obj); // OK
```

设计意图：多余属性检查是为了尽早发现"拼错属性名"或"传错配置项"这类笔误，而变量传递时多出来的属性通常是无害的。

## 5. object、Object 与 {} 的区别

三个看起来都像"对象"的类型，实际含义差别很大：

```ts
// object: 表示"任何非原始类型"(非number/string/boolean/symbol/bigint/null/undefined)
let a: object;
a = { name: "jack" }; // OK
a = [1, 2, 3];        // OK, 数组也是对象
a = () => {};         // OK, 函数也是对象
// a = 1;              // 报错

// Object(大写)和{}: 表示"任何非null/undefined的值", 范围比想象的大得多
let b: Object;
b = {};        // OK
b = "hello";   // OK! string也能赋给它
b = 123;       // OK!
// b = null;    // 报错

let c: {};
c = "hello";   // 同样OK
// c = undefined; // 报错
```

结论：

- 想表达"一个对象但属性不确定"，用 `object` 或 `Record<string, unknown>`（见 10 章），**不要用 `Object` 或 `{}`**
- `object` 只能赋值不能读属性，拿到后通常要配合类型收窄（09 章）或类型断言使用

## 6. 对象解构时的类型标注

函数参数解构对象时，类型标注要写在**整个解构模式后面**，不能写在每个属性后面：

```ts
type User = {
  name: string;
  age: number;
};

// 正确: 类型标注在整个{}之后
function printUser({ name, age }: User) {
  console.log(name, age);
}

// 错误写法: 这不是标注类型, 而是把name重命名成string类型的变量
// function printUser({ name: string, age: number }) {} // 报错
```
