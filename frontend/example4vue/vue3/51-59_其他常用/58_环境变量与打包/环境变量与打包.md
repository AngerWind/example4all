# 环境变量与打包(从package.json到环境变量使用全流程)

## 一、从 package.json 到启动项目

### 1. scripts 是什么

`package.json` 中的 `scripts` 定义了一组可以通过 `npm run <名字>` 执行的命令:

~~~json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
~~~

- `npm run dev` 实际执行的就是 `vite`
- `npm run build` 实际执行的就是 `vite build`
- **脚本名是随便起的**, 叫 `dev`/`start`/`serve` 都行, 真正决定行为的是右边的命令

### 2. 启动一个项目的标准流程

~~~bash
cd 项目目录
npm install      # 装依赖(第一次或依赖变化时才需要)
npm run dev      # 启动开发服务器, 终端会打印访问地址(如 http://localhost:5173)
~~~

日常开发循环:

~~~txt
npm run dev  →  改代码保存(浏览器热更新)  →  Ctrl+C停止  →  下班
~~~

### 3. 拿到陌生项目怎么看

1. **看 lock 文件选包管理器**: `package-lock.json`→npm, `pnpm-lock.yaml`→pnpm, `yarn.lock`→yarn
2. **看 package.json 的 scripts**: 决定启动命令是 `dev` 还是 `start` 还是别的
3. `npm run` 不带参数可以列出所有可用脚本

## 二、vite 怎么解析 mode

### 1. mode 是什么

mode(模式)是 vite 启动时确定的一个字符串, 它决定两件事:

- 加载哪些 `.env` 环境变量文件
- `import.meta.env.MODE`/`DEV`/`PROD` 的值

### 2. mode 从哪来(优先级)

~~~txt
命令行 --mode 参数  >  命令自带的默认值
~~~

| 实际执行的命令 | 默认 mode | 说明 |
|---|---|---|
| `vite`(开发服务器) | `development` | `npm run dev` 走这条 |
| `vite build`(构建) | `production` | `npm run build` 走这条 |
| `vite preview`(预览产物) | `production` | |
| `vite build --mode test` | `test` | `--mode` 无条件覆盖默认值 |

所以"npm run dev 加载 development 配置"并不是脚本名的功劳, 而是 **`vite` 这个命令默认 mode=development**。脚本名改成 `start` 效果一样。

### 3. mode 决定加载哪些文件

mode 确定后, vite 在项目根目录按**固定顺序**查找 4 类文件(以 mode=development 为例):

~~~txt
1. .env                    ← 所有情况都加载
2. .env.local              ← 所有情况都加载(本地私有, 不入git)
3. .env.development        ← 文件名后缀必须和mode完全一致
4. .env.development.local  ← 当前mode的本地私有版
~~~

- **文件名后缀必须和 mode 字符串完全一致**(大小写敏感): mode=`development` 永远**不会**加载 `.env.dev`; mode=`test` 就只会去找 `.env.test`
- 不存在的文件直接跳过, 不会报错

## 三、环境变量怎么合并

### 1. 合并规则

按上面 1→4 的顺序合并, **后加载的覆盖先加载的同名变量**, 所以 `.local` 文件优先级最高:

~~~txt
.env                      VITE_API=http://默认
.env.development          VITE_API=http://localhost:8080
.env.development.local    VITE_API=http://192.168.1.100:8080

最终: VITE_API=http://192.168.1.100:8080  (.local赢了)
~~~

### 2. 系统环境变量优先级最高

shell 里 export 的 `VITE_` 前缀系统环境变量, 会覆盖所有文件里的同名值:

~~~bash
# 临时覆盖, 不改任何文件
VITE_API_BASE_URL=http://临时地址 npm run build
~~~

### 3. 合并后的过滤(重要)

合并完成后, vite 会做一次过滤:

- **只有 `VITE_` 前缀的变量**才会暴露到客户端代码(`import.meta.env` 能访问到)
- 不带前缀的变量在浏览器代码里是 `undefined` —— 这是安全设计, 防止 `.env` 里的密钥被打进前端产物
- 不带前缀的变量仍可以在 `vite.config.ts` 里通过 `loadEnv()` 使用(见下文)

### 4. 最终生成的 import.meta.env

~~~js
import.meta.env = {
  ...所有VITE_前缀的变量,   // 值都是字符串
  MODE: 'development',      // 当前mode
  DEV: true,                // 仅当mode === 'development'时为true
  PROD: false,              // 仅当mode === 'production'时为true
  BASE_URL: '/',            // vite.config中的base
  SSR: false                // 是否服务端渲染
}
~~~

注意一个坑: 用 `vite build --mode test` 时, `MODE` 是 `'test'`, 但 `DEV` 和 `PROD` **都是 false**(只有development和production这两个特殊mode才会点亮对应的布尔值)。判断环境时优先用 `MODE`。

## 四、环境变量的命名区别

### 1. 文件名维度的区别

| 文件名 | 加载时机 | 是否提交git | 用途 |
|---|---|---|---|
| `.env` | 所有mode | 提交 | 团队共享的公共默认值 |
| `.env.local` | 所有mode | **不提交**(gitignore) | 你本机的私有覆盖 |
| `.env.development` | 仅mode=development | 提交 | 团队共享的开发环境配置 |
| `.env.development.local` | 仅mode=development | **不提交** | 你本机的开发环境私有覆盖 |
| `.env.production` | 仅mode=production | 提交 | 团队共享的生产环境配置 |
| `.env.test` | 仅mode=test | 提交 | 自定义mode的配置 |

记忆: **`.local` 后缀 = 本地私有**, 所以 `.gitignore` 里一般要加 `*.local`。

### 2. 变量名维度的区别

| 命名 | 能否在客户端代码访问 | 用途 |
|---|---|---|
| `VITE_xxx` | 能(`import.meta.env.VITE_xxx`) | 前端需要用的配置: 接口地址、应用名、开关等 |
| 不带前缀(如 `DB_PASSWORD`) | 不能(是undefined) | 只在构建阶段(vite.config.ts)使用的值 |

## 五、项目中怎么使用环境变量

### 1. 目录结构

`.env*` 文件放在**项目根目录**(和 package.json 同级):

~~~txt
my-project/
├── .env                  ← 所有环境都加载
├── .env.local            ← 本机私有覆盖(gitignore)
├── .env.development      ← 开发环境(npm run dev)加载
├── .env.production       ← 生产环境(npm run build)加载
├── src/
│   ├── App.vue
│   ├── main.ts
│   └── env.d.ts          ← 可选: 类型声明
├── .gitignore
├── package.json
└── vite.config.ts
~~~

### 2. 各文件内容示例

**.env**(公共默认值):

~~~ini
VITE_APP_NAME=我的应用
~~~

**.env.development**(开发环境):

~~~ini
VITE_API_BASE_URL=http://localhost:8080/api
~~~

**.env.production**(生产环境):

~~~ini
VITE_API_BASE_URL=https://prod.example.com/api
~~~

**.gitignore**(别忘了吗.local):

~~~txt
*.local
node_modules
dist
~~~

**src/App.vue**(在代码中读取):

~~~vue
<template>
  <div>
    <h3>应用名: {{ appName }}</h3>
    <h3>接口地址: {{ baseUrl }}</h3>
    <h3>当前模式: {{ mode }}</h3>
  </div>
</template>

<script setup lang="ts" name="App">
  // 通过import.meta.env.VITE_xxx读取
  const appName = import.meta.env.VITE_APP_NAME
  const baseUrl = import.meta.env.VITE_API_BASE_URL
  const mode = import.meta.env.MODE

  // 实际项目中常见用法: axios的baseURL
  // axios.create({ baseURL: import.meta.env.VITE_API_BASE_URL })
</script>
~~~

**src/env.d.ts**(可选, 让变量有类型提示):

~~~ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_APP_NAME: string
  readonly VITE_API_BASE_URL: string
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
~~~

**vite.config.ts**(构建阶段读取, 用loadEnv):

~~~ts
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({ mode }) => {
  // 第三个参数传''表示加载所有变量, 默认只加载VITE_前缀的
  const env = loadEnv(mode, process.cwd(), '')
  return {
    server: {
      proxy: {
        '/api': env.VITE_API_BASE_URL
      }
    }
  }
})
~~~

### 3. 最终效果

| 执行命令 | mode | 加载的文件 | `VITE_API_BASE_URL` 的值 |
|---|---|---|---|
| `npm run dev` | development | .env + .env.local + .env.development + .env.development.local | `http://localhost:8080/api` |
| `npm run build` | production | .env + .env.local + .env.production + .env.production.local | `https://prod.example.com/api` |
| `vite build --mode test` | test | .env + .env.local + .env.test + .env.test.local | 看.env.test里的定义 |

同一份代码, dev 时请求本地接口, build 后请求线上接口, 不用手动改代码。

## 六、常见坑总结

| 坑 | 说明 |
|---|---|
| 文件名必须叫 `.env.development` | `.env.dev` 不会被 mode=development 加载 |
| 改了 .env 要重启 dev server | env 只在启动时加载一次, 没有热更新 |
| 非 VITE_ 前缀访问不到 | `import.meta.env.SECRET_KEY` 是 undefined |
| 密钥不要放前端 | 前端产物是公开的, 任何变量都能被翻到; 真正的密钥放后端 |
| `--mode test` 时 DEV/PROD 都是false | 判断环境用 `MODE`, 别只用 `DEV`/`PROD` |
| `.local` 文件别提交 git | 在.gitignore中加`*.local` |
